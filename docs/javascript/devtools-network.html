NetworkタブでHTTP通信を読む
ステータスコードとヘッダーの見方

JavaScript・DevTools 2026/05/28

NetworkタブはHTTP通信の「盗聴器」

ページを開いたとき、裏では何十ものリクエストが飛んでいる。HTML本文・CSS・JavaScript・画像・フォント・API呼び出し……ブラウザはそれらをほぼ同時に処理している。

DevToolsのNetworkタブを開いてからページをリロードすると、これらの通信がすべて記録される。「なぜ画像が表示されないか」「なぜAPIが失敗するか」といった問題の原因は、ここを見れば大抵わかる。

DevTools を開く（F12） ↓ Networkタブをクリック ↓ ページをリロード（Ctrl+R / Cmd+R） ↓ 全リクエストが一覧表示される

Network タブを開いた後にリロードしないと記録が始まらない点に注意。開く前の通信は記録されていない。

リクエスト一覧の読み方

一覧には複数の列が表示される。よく使う列とその意味を確認しておこう。

列名内容
Nameファイル名またはURL。クリックするとリクエスト詳細が開く
StatusHTTPステータスコード（後述）
Typeリソースの種類。document / script / stylesheet / image / xhr / fetch など
Sizeファイルサイズ。グレー表示はキャッシュから取得したことを示す
Timeレスポンスが返ってくるまでの時間

ステータスコード早見表

Statusの数字はHTTPの「返答コード」だ。3桁の数字で意味が決まっている。

コード意味よくある状況
200 OK成功通常のリクエスト成功
301 / 302リダイレクトURLが変わった、http→httpsへ転送
304 Not Modifiedキャッシュを使用前回と内容が変わっていないためキャッシュから返した
401 Unauthorized認証が必要ログインが必要なAPIに未認証でアクセスした
403 Forbiddenアクセス禁止認証済みでもアクセス権がない
404 Not Foundファイルが存在しないURLを間違えた、ファイルを削除した
500 Internal Server Errorサーバー側のエラーサーバーのプログラムがクラッシュした
色でも大まかに判断できる：
2xx（緑）→ 成功、3xx（青）→ リダイレクト、4xx（オレンジ）→ クライアントエラー、5xx（赤）→ サーバーエラー。DevToolsによっては色分けされている。

ヘッダーを読む

一覧のリクエスト名をクリックすると右パネルが開く。「Headers」タブに Request Headers と Response Headers が表示される。

Request Headers — ブラウザからサーバーへ

ブラウザがサーバーに送る「付加情報」だ。

ヘッダー名内容
User-Agentどのブラウザ・OSからのリクエストか
CookieセッションIDなどのCookie情報（自動付与）
Authorization認証情報。Basic認証（Basic xxxxxx）やBearerトークン（Bearer eyJ…）
Refererどのページからリンクをたどってきたか
Content-TypePOSTリクエスト時に送るデータの形式（application/json など）

Response Headers — サーバーからブラウザへ

サーバーが返す「返答情報」だ。

ヘッダー名内容
Content-Type何のファイルか（text/html, image/png, application/json など）
Cache-Controlキャッシュ方針。no-cache / max-age=86400 など
Set-Cookieこのレスポンスで新たにCookieをセットする
Access-Control-Allow-OriginCORS設定。どのオリジンからのアクセスを許可するか
Location3xxリダイレクト時の転送先URL

フィルターの使い方

多くのリクエストが並ぶときは、フィルターバーで絞り込むと目的のリクエストを探しやすい。

フィルター表示されるもの
All全通信
Fetch / XHRJavaScriptからのAPI通信（fetch・XMLHttpRequest）
Img画像リクエストのみ
JSJavaScriptファイル
CSSスタイルシートファイル
DocHTMLドキュメント本体

さらに2つのチェックボックスを覚えておくと便利だ。

Disable cache：チェックするとキャッシュを使わず全リクエストをサーバーに投げる。「Provisional headers are shown」が出たときや、最新のレスポンスヘッダーを確認したいときに使う。DevToolsを開いている間だけ有効。
Preserve log：チェックするとページ遷移・リダイレクトが起きても記録が消えない。ログイン後のリダイレクト通信を追いたいときに必須。

"Provisional headers are shown" とは

Networkタブでリクエストをクリックしたとき、Headers欄に次のような警告が出ることがある。

Provisional headers are shown. Disable cache to see full headers.

これはブラウザがキャッシュからレスポンスを返したため、実際にサーバーへリクエストが飛んでおらず、本当のリクエストヘッダーが取得できていない状態を意味する。

特に Authorization ヘッダーが付いているかどうかを確認したいときに、この警告が出ると何も見えないので詰まりやすい。

解決方法：
「Disable cache」にチェックを入れてリロードする。キャッシュを使わず実際にサーバーへリクエストが飛ぶため、全ヘッダーが表示される。
DevTools を開いた状態で ↓ Networkタブ → 「Disable cache」にチェック ↓ ページをリロード ↓ 実際のリクエストヘッダーが確認できる

確認が終わったら「Disable cache」のチェックは外しておこう。チェックを入れたままだとキャッシュが効かないため、ページ読み込みが毎回遅くなる。
