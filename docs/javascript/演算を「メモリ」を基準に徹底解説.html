JavaScriptの演算をメモリを基準に解説して

JavaScriptは「メモリ操作の言語」

JavaScriptの演算はすべて、

メモリにある値を取り出し → 計算 → 結果をメモリに戻す

という流れで動いています。

変数 = メモリ上の箱
let a = 10;
let b = 3;

これは👇こういう意味です。

メモリ

+ ------ +
|　 a 　| → 10
+ ------ +
|　 b 　| → 3
+ ------ +

👉 変数 = メモリアドレスに付けた名前

演算の本当の流れ（超重要）
let c = a + b;

メモリ内部で起きている流れ
1️⃣ メモリから a の値を読み出す → 10
2️⃣ メモリから b の値を読み出す → 3
3️⃣ CPUが計算 → 10 + 3 = 13
4️⃣ 結果を c に保存

+ ------ +
| 　a 　| → 10
| 　b　 | → 3
| 　c　 | → 13
+ ------ +

👉 演算 = メモリ → CPU → メモリ

代入演算子の正体
a += 5;

これは省略形で、実際は：

a = a + 5;

メモリ上の流れ

a → 10
↓ 読み出す
10 + 5 = 15
↓ 書き戻す
a → 15

👉 「同じ変数を左右で使う」＝ 取り出して更新

インクリメントのメモリ動作
a++;

これは：

a = a + 1;

メモリ動作

a → 10 → 11

比較演算もメモリ操作
a > b;

内部処理

  1. a を読み出す
  2. b を読み出す
  3. CPUで比較
  4. true / false を生成

結果 → true（これは一時的な値）

let result = a > b;

result → true
参照型と値型（ここ超重要）

プリミティブ型（値型）

  • number
  • string
  • boolean
  • null
  • undefined
  • symbol
  • bigint
let x = 10;
let y = x;

メモリ状態

x → 10
y → 10（コピー）

y = 20;

x → 10
y → 20

👉 完全コピー

参照型（オブジェクト・配列・関数）

let obj1 = { a: 10 };
let obj2 = obj1;

メモリ構造

obj1 → [アドレス1000]
obj2 → [アドレス1000]

1000 → { a: 10 }

👉 アドレスを共有

obj2.a = 99;

obj1.a → 99
obj2.a → 99

⚠ ここでバグが激増する

演算と参照の組み合わせ（最重要）
let arr = [1, 2, 3];
let arr2 = arr;

arr2.push(4);

メモリ

arr → [1000]
arr2 → [1000]

1000 → [1, 2, 3, 4]

👉 同じ配列を操作している

正しくコピーする（ディープコピー）
let arr2 = [...arr];

arr  → [1000]
arr2 → [2000]

1000 → [1,2,3]
2000 → [1,2,3]
なぜ「メモリ基準」で考えるとバグが減るのか
let a = [1,2];
let b = a;

b.push(3);
console.log(a); // [1,2,3] ← なぜ！？

👉 参照共有を理解していないと一生ハマる

プロが頭の中で見ている世界

プロはコードを読む時、こういうメモリ図を頭に描いています👇

変数 → アドレス → 実データ

これができると：
✅ バグ激減
✅ React / Vue の理解爆速
✅ 非同期処理も簡単
✅ オブジェクト操作が直感的

超重要まとめ
観点 本質
変数 メモリのラベル
演算 メモリ→CPU→メモリ
代入 メモリの書き換え
比較 値を取り出して判定
参照 アドレス共有
バグ 参照の誤解
