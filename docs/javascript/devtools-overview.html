Chrome DevToolsとは
6つのタブの役割と使い分け

JavaScript・DevTools 2026/05/28

DevToolsを開く

Chrome DevToolsは、Webページの内側を調べるためのブラウザ内蔵ツールだ。開き方は2通りある。

方法①: キーボードショートカット → F12 方法②: ページ上で右クリック → 「検証」を選択

DevTools は Chrome 専用ではない。Edge・Firefox にも同様のツールが備わっており、基本的なタブ構成はほぼ共通だ。名称や細かい配置が異なる程度で、操作感はほとんど変わらない。

一言で言えば、DevTools は Webページを「外から見る」ツールだ。ソースを書き換えるわけではなく、ブラウザが受け取ったデータをリアルタイムで観察・仮編集できる。

6タブの役割一覧

DevTools を開くと上部にタブが並ぶ。代表的な6つの役割をまとめた。

タブ名主な用途
ElementsHTMLの構造・CSSをリアルタイムで確認・編集
ConsoleJS実行・エラー確認・document.cookieなど
SourcesJSファイルの中身を見る・ブレークポイント
NetworkHTTPリクエスト・レスポンスを監視する
ApplicationlocalStorage・Cookie・IndexedDBを確認
Performanceページの描画速度・処理のボトルネック分析

どのタブも「ページを壊さず観察する」という点は共通だ。Elements で HTML を書き換えても、ブラウザをリロードすれば元に戻る。

「どのタブをいつ使うか」フローチャート

問題の種類によって、まず開くべきタブが変わる。

CSSがおかしい（レイアウト崩れ、色が当たらない） → Elements タブ JSエラーが出た（Uncaught TypeError など） → Console タブ 通信がうまくいかない / 画像が表示されない → Network タブ ログイン状態が消える / localStorage を確認したい → Application タブ ページが重い・カクつく → Performance タブ
迷ったらまず Console を開く。
エラーメッセージが出ていれば、そこに問題の手がかりが書いてある。Console は「ページの健康診断」として最初に確認する習慣をつけると良い。

開発者だけのツールではない

「DevTools = エンジニアのもの」というイメージがあるが、それは正確ではない。

デザイナーが使う場面として、Elements タブでフォントサイズ・余白・配色を実際のページ上で確認するケースがある。Figma 上のデザインとブラウザ描画を比較するときに便利だ。

授業課題でエラーが出たときは、Console を開くと何行目で何のエラーが起きているかが一目でわかる。エラー文を読まずに「動かない…」と悩む前に、DevTools を開くのが最短の解決策だ。

まず開く習慣をつける：
何かおかしいと感じたら F12 を押す。Console にエラーがあればそこから調べる。エラーがなければ Elements や Network を確認する。この順番を習慣にするだけで、デバッグにかかる時間が大幅に減る。

スクレイピングや認証の調査にも DevTools は活用できる。Network タブでリクエストヘッダーや Cookie を確認することで、Webページがどのように通信しているかを把握できる。
