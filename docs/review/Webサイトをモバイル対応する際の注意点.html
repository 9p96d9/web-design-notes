Webサイトをモバイル対応する際の注意点

レスポンシブ実践 2026/01/08

Webサイトをモバイル対応する際の注意点

  • プロンプト例

Webサイトをモバイル対応ページに変更を加えるときの注意点

レイアウト設計の注意点

① モバイルファースト設計
PCデザインを縮小するのではなく、モバイルを起点に設計する方が破綻しにくい。

/* モバイル基準 */
body { font-size: 16px; }

/* 768px以上でPC対応 */
@media (min-width: 768px) {
  body { font-size: 18px; }
}

ポイント

  • 小画面 → 大画面の拡張
  • 情報の優先順位を明確化
② 横スクロールの完全排除

モバイルでは横スクロールは致命的UX劣化。

img, video {
  max-width: 100%;
  height: auto;
}

チェック項目

  • width固定(px)の要素がないか
  • overflow: hidden; で無理に隠していないか
③ 1カラム構成が基本
  • PC：2～3カラム
  • モバイル：1カラム縦積み
@media (max-width: 767px) {
  .container {
    display: block;
  }
}

操作性（UI/UX）の注意点

④ タップ領域の最適化
  • 最低44px四方（Apple推奨）
button, a {
  min-height: 44px;
}

注意

  • リンクが密集 → 誤タップ増加
  • hover前提UI → モバイルで破綻
⑤ ハンバーガーメニュー設計
  • メニュー階層は最大2階層
  • 開閉アニメーションは軽量に
nav {
  position: fixed;
  top: 0;
  right: 0;
}
⑥ フォントサイズと行間
body {
  font-size: 16px;
  line-height: 1.7;
}

目安

  • 最小16px
  • 行間 1.6〜1.8

パフォーマンスの注意点

⑦ 画像の軽量化（最重要）

  • WebP / AVIF 使用
  • 適切なサイズ配信
<img src="image.webp" loading="lazy" alt="">
⑧ 不要なJavaScriptの削減
  • モバイル回線ではJS過多＝体感速度悪化

対策

  • jQuery依存を減らす
  • IntersectionObserver で遅延読み込み

フォーム設計の注意点

⑨ 入力補助の活用
<input type="email" inputmode="email">
<input type="tel" inputmode="tel">

効果

  • スマホキーボード最適化
  • 入力ミス削減
⑩ フォーム項目の最小化
  • モバイルでは入力負荷＝離脱率

原則

  • 必須項目のみ
  • 入力補助（自動入力・候補）

デザインの注意点

⑪ 情報量を詰め込みすぎない
  • 余白はPCより広め
  • 一画面一目的設計
⑫ ファーストビュー最適化
  • 3秒以内に「何のサイトか」分かる

構成例
　キャッチコピー
　↓
　サービス概要
　↓
　行動導線（CTA）

実務チェックリスト（現場用）

  • viewport 設定済みか
  • 横スクロール発生していないか
  • タップ領域44px確保
  • 画像サイズ適正か
  • フォーム入力が楽か
  • JSが過剰でないか
  • 3G回線で体感速度が許容範囲か
現場でよくある失敗
失敗例 問題点
PCデザインを縮小 情報過多
hover依存UI 操作不能
px固定レイアウト 崩壊
画像未圧縮 表示遅延
小さなリンク 誤操作
実務で使える基本ブレイクポイント
/* スマホ */
@media (max-width: 767px) {}

/* タブレット */
@media (min-width: 768px) and (max-width: 1023px) {}

/* PC */
@media (min-width: 1024px) {}
