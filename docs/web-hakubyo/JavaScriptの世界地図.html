JavaScriptの世界地図
Node.js・npm・React・TypeScript・Next.jsを整理する

Webリテラシー 2026/05/19

「JSだけで作ってた世界じゃなくなってる？」

HTMLとCSSを覚えて、JavaScriptも少し書けるようになった。PHPでサーバーの仕組みも触った。

なのに最近、こんな言葉が急に増えてきていないか？

  • Node.js
  • npm install
  • React
  • TypeScript
  • Next.js

「なんかJavaScriptの周りが複雑になってる気がする」という感覚は正常だ。
これらは全部つながっている。ひとつひとつ地図として整理していこう。

まず大前提：HTML・CSS・JSは今も変わらない

ReactもNext.jsも、最終的にブラウザが受け取るのは HTML・CSS・JS だ。
これは変わっていない。

素材役割今も使われる？
HTML骨組み・構造✅ 変わらない
CSS見た目・レイアウト✅ 変わらない
JavaScript動き・ロジック✅ 変わらない

では「Node.js・React・TypeScript」は何者か？
これらは HTML/CSS/JS を もっと快適に・大規模に 扱うための道具だ。

① Node.js ── JSをブラウザの外で動かす装置

もともとJavaScriptは ブラウザ専用言語 だった。
ChromeやFirefoxの中でしか動かなかった。

PHPを思い出してほしい。PHPは サーバー側で動く言語 だ。

  • ユーザーがURLにアクセス
  • サーバー上のPHPが処理
  • HTMLを生成してブラウザへ返す

2009年、Node.js が登場した。

Node.js = JavaScriptをPCやサーバー上で動かす仕組み
ブラウザがなくてもJSが動く。PHPと同じ「サーバーサイド言語」として使える。

これによって、フロント（見た目）もサーバー（処理）も、同じJavaScriptで書けるようになった。
「フロントエンドエンジニア」が「バックエンドも触れる」時代の始まりだ。

② npm ── パッケージ管理ツール

Node.jsと一緒に覚えておきたいのが npm（Node Package Manager）だ。

PHPで言えば Composer に近い。「ライブラリをダウンロードして管理する道具」だ。

# Reactを使えるようにする npm install react # Tailwind CSSを入れる npm install tailwindcss # Reactプロジェクトをまるごと作る npm create vite@latest

npm install ○○ を打つだけで、世界中の開発者が作ったライブラリを使えるようになる。
「GitHubのアプリストア」と思えばいい。

③ React ── 画面を「部品」で作る考え方

Webサービスが大きくなると、素のJavaScriptだけでは管理が辛くなる。

// 昔のJS: 全部手書きでDOMを操作する document.getElementById('app').innerHTML = '<div class="card">...</div>'; document.getElementById('btn').addEventListener('click', () => { ... }); document.getElementById('count').textContent = count;

画面の部品が増えるたびに、こういうコードが何百行にもなる。
Reactはこの問題を解決するために作られた。

考え方は「画面を コンポーネント（部品） に分ける」だ。

// React: 部品として定義する function UserCard({ name, age }) { return ( <div className="card"> <h2>{name}</h2> <p>{age}歳</p> </div> ); } // どこでも使い回せる <UserCard name="田中" age={25} /> <UserCard name="鈴木" age={32} />

「ボタン」「カード」「ナビゲーション」を部品にして組み合わせる。
Webサービスをレゴブロックのように作る感覚だ。

Reactの書き方は JSX と呼ばれ、JavaScriptの中にHTMLを書く形式になっている。最初は奇妙に見えるが、すぐ慣れる。

④ TypeScript ── JSに「型」をつけたもの

PHPには「型」という概念がある。JavaScriptは自由度が高すぎて、大規模開発でバグが起きやすい。

// JavaScript: 何でも入る（問題になりやすい） let price = "1000"; price = 1000; price = true; // 全部OK… // TypeScript: 型を指定する let price: number = 1000; price = "1000"; // ← エラー！ 数字じゃない

TypeScriptは「型を付けたJavaScript」だ。
書いたコードが 実行前にチェックされる ので、バグを早期発見できる。

最終的にJavaScriptに変換されて動く。ブラウザはTypeScriptを直接読めない。

TypeScript は「安全にJSを書くためのツール」
今の業界では React + TypeScript が標準的な組み合わせになっている。

⑤ Next.js ── Reactをまとめた「全部入りセット」

Reactは「画面の部品を作る」ことに特化している。でも実際のWebサービスにはこれだけでは足りない。

必要な機能Reactだけ？Next.jsなら？
ページ遷移（ルーティング）別で追加が必要✅ 標準装備
SEO対策弱い✅ 対応済
サーバー処理できない✅ 組み込み
画像最適化自分で実装✅ 自動最適化
TypeScript対応設定が必要✅ デフォルト対応

Next.jsを使えば「ReactでWebサービスを作る」ためのほぼ全部が揃っている。
今の業界で「Reactでサービスを作る」と言えば、多くの場合 Next.jsを使う。

全体の地図

ここまでをまとめると、こういう構造になっている。

HTML / CSS / JavaScript　←　今も土台は同じ 　　↓　複雑化・大規模化 Node.js　　：JSをサーバーで動かす npm　　　　：ライブラリを管理する React　　　：画面を部品で作る TypeScript　：型でバグを防ぐ 　　↓　全部まとめると Next.js　　：全部入りセット 　　↓　公開 Vercel / AWS などにデプロイ

「なんかJSだけで作ってた世界じゃなくなってる」という感覚は正しい。でも積み上がってる。
ReactもNext.jsも、最終的にはHTML+CSS+JSを出力している。基礎は一切無駄じゃない。

実際に作ったWebアプリを覗いてみる

ここまで説明してきた技術が「実際のWebアプリでどう使われるのか」を見てみよう。

ポーカーのプレイ記録を自動で収集して、GTO（Game Theory Optimal・ゲーム理論最適戦略）の観点からAIが分析するWebアプリを作った。

要素使った技術この記事で言うと
ブラウザ拡張機能Chrome Extension（JS）素のJavaScript
リアルタイム通信の傍受WebSocket + JSJSのネットワーク機能
データベースFirebase FirestoreクラウドDB
ログイン認証Firebase Auth（Google認証）外部サービス連携
サーバー（バックエンド）FastAPI（Python）PHPの代わりにPythonでサーバー処理
AI分析Groq / Gemini APIAIサービスのAPI利用
PDF生成WeasyPrint（Python）サーバー側での出力処理
デプロイ先AWS EC2（クラウドサーバー）Vercelの代わりにAWSを使う選択肢
自動デプロイGitHub ActionsGitHubの自動化機能（CI/CD）

このアプリはNext.jsではなくPythonのFastAPIをサーバーに使っているが、「クライアント（ブラウザ）とサーバーが通信する」という構造はまったく同じだ。

技術の選択肢は1つではない。Node.js/Next.jsはJS系の王道。FastAPI/DjangoはPython版。目的は同じで、アプローチが違う。

大事なのは「どの言語・ツールか」より「何ができるかを理解すること」
HTML・CSS・JSの基礎を持っていれば、どの方向にも広げられる。

次のステップ

「実際に動かしてみたい」という人へ、最短コースを紹介する。

ステップやること目安
1Node.jsをインストールして node -v で確認10分
2npm create vite@latest でReactプロジェクトを作る15分
3コンポーネントを1つ自分で書いてみる1時間
4TypeScriptに切り替えて型エラーを体験する30分
5npx create-next-app でNext.jsを試す15分

まずは「動かす」こと。概念は体で覚えると定着が早い。
