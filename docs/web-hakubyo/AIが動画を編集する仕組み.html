AIが動画を編集する仕組み
FFmpegとClaude Codeの正体

Webリテラシー 2026/05/19

「AIが動画を編集した」は正しいか？

Claude Codeに「この動画を切ってつなげて」と頼んだら、実際に動画が完成した。

すごい。でも「AIが動画編集した」というのは、正確じゃない。

実際に起きていたのはこうだ。

Claude Code（AI） 　↓　コマンドを自動生成 ターミナル（PowerShell） 　↓　コマンドを実行 FFmpeg（動画処理ツール） 　↓　実際に動画を切る・つなぐ 完成した動画ファイル

本体はFFmpeg。 AIはそれを呼び出す「司令官」だ。

FFmpegとは何か

FFmpegは「動画界の包丁」と呼ばれることがある。

1つのツールで、動画に関するほぼ全てができる。

できることコマンド例
動画を切るffmpeg -i input.mp4 -ss 10 -t 30 output.mp4
動画をつなぐffmpeg -f concat -i list.txt output.mp4
音声だけ抜くffmpeg -i input.mp4 -vn audio.mp3
GIFに変換ffmpeg -i input.mp4 output.gif
ファイルサイズを圧縮ffmpeg -i input.mp4 -crf 28 output.mp4
解像度を変えるffmpeg -i input.mp4 -vf scale=1280:720 output.mp4
字幕を焼き込むffmpeg -i input.mp4 -vf subtitles=sub.srt output.mp4

YouTubeの動画処理、配信ソフトのOBS、AIの音声・映像パイプライン。
業界の裏側でFFmpegが動いている場面は多い。

コマンド1行で完結する。GUIアプリを使わなくていい。これが強みだ。

Claude Codeの正体

「AIがコードを書いてくれる」「AIがファイルを操作してくれる」

これを「魔法」だと思っていないか？

かなり雑に言うと、Claude Codeは：

AI + ターミナル自動操作
人間がキーボードで打つコマンドを、AIが自動生成して実行しているだけ。

今回の動画編集で実際にやったことを分解するとこうだ。

AI：「FFmpegがインストールされているか確認する」
ffmpeg -version
PC：「あるよ」

AI：「動画を前半・後半に切る」
ffmpeg -i "2A.mp4" -ss 00:00:00 -t 00:01:30 "part_a.mp4"
PC：「完了」

AI：「2つをつなぐためのリストファイルを作る」
file 'part_a.mp4' file 'part_b.mp4'
FFmpeg：「文字コードが壊れてる、読めない」

AI：「ASCII文字コードで作り直す」
[System.Text.Encoding]::ASCII.GetBytes(...)
FFmpeg：「OK、つなげた」

AI：「一時ファイルを削除して完了」

これだけ。人間がターミナルで打つのと、やっていることは同じだ。

  • 処理速度・進捗フレーム数
  • エラーメッセージ

全部ログに出る。これは昔からの文化で、今でも変わっていない。

エラーの正体 — BOMと文字コード問題

今回のエラーの一つは、こういうメッセージだった。

unknown keyword '﻿file'

「file」という単語の前に見えない文字がついていた。

これが BOM（Byte Order Mark） だ。

BOMとは
UTF-8ファイルの先頭に自動で挿入される「不可視文字」。
Windows環境でテキストファイルを作ると付くことがある。
人間の目には見えないが、プログラムは読んでしまう。

FFmpegのconcatは、リストファイルの最初の文字が file であることを期待している。
でもBOM付きだと、最初の文字は ﻿file（見えない文字 + file）になってしまう。

解決策は「BOMを付けないASCIIで書き直す」だった。

# BOM付きUTF-8（Windows標準）→ FFmpegが認識できない ﻿file 'part_a.mp4' # ASCII → FFmpegが正常に読める file 'part_a.mp4'

目に見えないバグ。こういう問題が現場では頻繁に起きる。

現代AI開発の実態

「AIは魔法」ではない。AIがやっていることは：

AI 　↓　指示を解釈してコマンドを生成 Node.js / Python / PowerShell 　↓　実行環境 FFmpeg / Git / Docker / AWS CLI 　↓　実際の処理 ファイル・サーバー・クラウド

AIは「既存ツールのオーケストラ指揮者」だ。

楽器（FFmpeg・Git・Docker）は昔からある。
AIが登場したことで、それらを組み合わせる「司令塔」が自動化された。

やりたいことAIが呼び出すツール
動画を編集するFFmpeg
コードを管理するGit
サーバーを動かすDocker
クラウドにデプロイAWS CLI
画像を処理するImageMagick
PDFを生成するWeasyPrint / Puppeteer

AIが賢くなっているのではなく、AIが扱える道具の種類が増えている。

AI時代に強い人とは

「Pythonの文法を全部暗記している人」は強いか？

今の時代、コードの書き方はAIが補完してくれる。

では、何が差になるか。

裏で何が起きているかを理解できる人
エラーを見て「BOMの問題だ」と見抜ける。
ログを見て「ここのパスがおかしい」と判断できる。
AIの出力を「正しいか間違いか」検証できる。

今回のBOMの話。パスの話。FFmpegの仕組み。

これは「覚えなくていい細かい知識」ではなく、「起きていることを読む力」 の話だ。

HTML・CSS・JS・PHPを学んだ時間は、その「読む力」の土台になっている。

FFmpegを試すなら

インストールして、コマンドを1つ打ってみるだけでいい。

OSインストール方法
Windowsffmpeg.org からZIPをDL、PATHを通す
Macbrew install ffmpeg
Linuxsudo apt install ffmpeg
# インストール確認 ffmpeg -version # 動画の情報を見る（何も変換しない） ffmpeg -i input.mp4 # 動画を10秒だけ切り出す（0秒〜10秒） ffmpeg -i input.mp4 -ss 0 -t 10 -c copy output.mp4

「コマンドを打って何かが起きる」体験をすると、ログの意味が分かるようになる。

AIに頼む前に、自分で1回やってみる。それだけで理解の深さが変わる。
