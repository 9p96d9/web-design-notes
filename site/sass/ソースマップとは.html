ソースマップとは

Sass基礎 2026/04/09

ソースマップ（.css.map）とは？

sass でコンパイルすると、style.css と一緒に style.css.map が自動生成されます。

このファイルは、「コンパイル後のCSSの各行が、元のSCSSのどこに対応するか」を記録した対応表です。

scss/style.scss（あなたが書くファイル）
    ↓ コンパイル
css/style.css  ＋  css/style.css.map  ← ← ← 対応表

ブラウザのDevToolsで何が変わるか

ブラウザの「要素を検査」でスタイルを確認したとき、表示が変わります。

状態DevToolsに表示されるファイル
ソースマップありstyle.scss:42（SCSSの元の行）
ソースマップなしstyle.css:187（コンパイル後の行）

SCSSの行が表示されると、「このスタイルはどこで書いたか」がすぐ特定できます。デバッグ効率が大幅に上がります。

ファイルの中身（参考）

JSONで書かれています。直接編集する必要はありません。

{
  "version": 3,
  "sources": ["../scss/style.scss"],  // 元ファイルのパス
  "mappings": "...",                  // 位置の対応表（エンコードされた文字列）
  "file": "style.css"
}
  • sources：元のSCSSファイルのパス
  • mappings：CSSの各行がSCSSのどの行に対応するかの対応表（Base64エンコード）
  • file：このソースマップが対応するCSSファイル名

本番環境では不要な場合がある

ソースマップはデバッグ用ファイルです。本番環境（公開サイト）では：

  • ソースマップがあると内部構造が見えやすくなる（セキュリティ面の懸念）
  • ファイルサイズが増える

本番ビルドでは生成しないこともあります。

# ソースマップを生成しない
sass --no-source-map scss/style.scss css/style.css
使い分けの目安
環境ソースマップ
開発中（ローカル）あり（デフォルト）
本番環境状況による（なしにすることも多い）
学習・練習あってもなくても問題なし

まとめ

  • .css.map は Sass のコンパイル時に自動生成されるデバッグ用ファイル
  • ブラウザの DevTools で「SCSSの元の行」が見えるようになる
  • 直接編集する必要はない
  • 本番環境では --no-source-map で生成を抑制できる
